🗺️ 旅程時間線

Phase 1：從零到裸機部署

📅 2026.05.10

一切從一台 Zeabur 提供的 Ubuntu 24.04 VPS 開始。伺服器上已經有 Zeabur 預裝的 k3s 和管理面板。

做了什麼

  • 在伺服器上直接用 PM2 + Nginx 部署韓文學習平台（Next.js 16）
  • 設定 UFW 防火牆：只開放 22 (SSH)、80/443 (HTTP/HTTPS)
  • Nginx 設定安全 headers（X-Frame-Options、XSS Protection 等）
  • 將域名 shawnlin.online 從 GoDaddy 遷移到 Cloudflare（免費 SSL + DDoS 保護）

遇到的坑

  • Port 80/443 被 Hermes Agent gateway 佔用 → 先用 8080/8443
  • Cloudflare 預設連 origin port 80，但 Nginx 在 8080 → Error 522
  • GoDaddy DNS 界面難用，果斷遷移到 Cloudflare
💡 為什麼這樣做：先從最簡單的 PM2+Nginx 開始，理解「應用程式 → Process Manager → Reverse Proxy → DNS → CDN」這條鏈路。每一步都親手操作過，才知道每個環節的作用。

Phase 2：容器化 & 遷移到 K3s

📅 2026.05.11

做了什麼

  • 為 Next.js 專案寫 multi-stage Dockerfile（standalone output）
  • 安裝 Docker、建立映像檔、匯入 k3s 的 containerd
  • 建立 korean-learning namespace，隔離 Zeabur 系統
  • 用 Helm 安裝 ingress-nginx（DaemonSet + hostNetwork）
  • 移除 Zeabur 的 ingress controller，收回 port 80/443
  • 從 Cloudflare Tunnel 切換到自管 Ingress

關鍵決策

決策原因
用 k3s 而非 Docker Compose學習真正的 K8s，且 Zeabur 已預裝 k3s
自管 ingress-nginx全自管哲學：不依賴 Zeabur 或 Cloudflare Tunnel
imagePullPolicy: Never無 remote registry，映像檔手動 import 到 containerd
DaemonSet + hostNetwork單節點叢集，直接綁定 host port 最簡單
⚠️ 踩坑：npm ci --omit=dev 會移除 TailwindCSS → Next.js build 失敗。Dockerfile 的 builder stage 要用 npm ci（含 devDependencies）。

Phase 3：微服務架構 & API Gateway

📅 2026.05.11–05.12

做了什麼

  • 將單體 Next.js 拆分為 5 個微服務：frontend、api-gateway、user-service、vocab-service、quiz-service
  • API Gateway 用 Express + http-proxy-middleware 做路由轉發
  • PostgreSQL StatefulSet 作為持久層
  • 全部寫成 Helm Chart，一個 chart 管所有服務

架構

Browser → Cloudflare → Ingress → Frontend (Next.js :3000)
                                    ↓ (rewrites)
                              API Gateway (:4000)
                           ┌────────┼────────┐
                     /auth  ↓   /vocab ↓  /quiz ↓
                  user-svc  vocab-svc  quiz-svc
                   (:4001)   (:4002)   (:4003)
                                    ↓
                              PostgreSQL

踩坑三連發

  1. Next.js rewrite 指向 localhost：next.config.ts 的 destination 是 http://localhost:4000，在 K8s 裡 localhost 是 Pod 自己 → 改為 http://api-gateway:4000（K8s Service DNS）
  2. express.json() 吃掉 POST body：api-gateway 先 express.json() 再 proxy，導致 POST 請求 body 被消費 → 只在 health route 用 json parser
  3. http-proxy-middleware v3 path 被 strip：app.use('/api/auth', proxy) 會把 /api/auth 從路徑中移除 → 改用 pathFilter 保留完整路徑
✅ 成果：註冊、登入、單字查詢、測驗全部通過。API 從前端到資料庫的整條鏈路打通。

Phase 5：監控 & 告警

📅 2026.05.12–05.13

做了什麼

  • 部署 kube-prometheus-stack（Prometheus + Grafana + Alertmanager）
  • 部署 Loki + Promtail 做 log 聚合（7 天保留）
  • 設定 11 條 PrometheusRule 告警：Disk、Memory、CPU、Pod crashloop、Pod not-ready、Postgres down、PVC 容量
  • 寫 alert-checker.py（每 5 分鐘透過 k8s API proxy 查 Prometheus）
  • 寫 uptime-watchdog.py（每 2 分鐘檢查網站是否活著）

Grafana sidecar OOMKill 事件

  • Grafana 的 grafana-sc-dashboard、grafana-sc-datasources sidecar 被 OOMKill
  • 原因：ResourceQuota 要求所有容器宣告 limits，但 Helm chart 預設 sidecar 沒有
  • 初版設 32Mi memory limit → 不夠，sidecar 需要 ~100Mi+
  • 最終設 128Mi，解決 CrashLoopBackOff
💡 學到：ResourceQuota 要求所有容器（含 init container 和 sidecar）都宣告 limits。Helm chart 的 sidecar 常常沒設，需要手動 patch。ReadWriteOnce PVC 在滾動更新時會衝突，需要 scale down 再 up。

🔧 技術教訓

#問題根因解法
1 Next.js rewrite 失效 destination 寫 localhost 而非 K8s Service DNS http://api-gateway:4000
2 POST API 卡住 express.json() 在 proxy 之前吃掉 body 只在 health route 用 json parser
3 proxy 路徑被 strip http-proxy-middleware v3 預設行為 用 pathFilter 保留路徑
4 Pod ErrImageNeverPull Helm --set 蓋掉 image 為 Docker Hub 路徑 + imagePullPolicy: Never helm upgrade 重設 image 為 local
5 CPU 排程失敗 單節點 requests 96%，新 Pod 無法排程 staging 用 10m CPU request
6 Grafana sidecar OOMKill ResourceQuota 要求的 32Mi memory limit 不夠 提升到 128Mi
7 ArgoCD 308 redirect loop Cloudflare HTTPS → ArgoCD 強制 HTTPS server.insecure=true
8 Port 80/443 被佔用 Zeabur ingress controller + Hermes gateway 移除 Zeabur、設定 ingress-nginx hostNetwork

🏗️ 架構原則

  1. 全自管：不依賴 PaaS，每個元件都要理解並親手部署
  2. 漸進式：PM2 → Docker → K8s → Helm → GitOps，一步一步來
  3. 真實專案驅動：用韓文學習平台當案例，不是憑空練習
  4. 隔離：Namespace 隔離環境、ResourceQuota 防止資源爭搶
  5. 可觀測：監控 + 告警 + Log 聚合，出事了才知道
  6. Git 是唯一真相來源：ArgoCD 確保叢集狀態 = Git 狀態
