💡 kubectl 看資源使用：top + describe node Allocated

kubectl top nodes 看各節點即時 CPU% 用量，kubectl top pods -A 看各 Pod 實際消耗。用 kubectl describe node | grep -A 8 Allocated 看 requests/limits 佔比（scheduler 視角）。top 反映即時壓力，describe Allocated 反映理論容量限制。

# 節點即時用量
kubectl top nodes

# 所有 Pod 即時用量
kubectl top pods -A

# 節點資源分配比例（request/limit 佔總容量 %）
kubectl describe node <node-name> | grep -A 8 Allocated

💭 原理：top 是即時指標（由 metrics-server 提供），describe Allocated 是 scheduler 看到的已分配資源比例。兩者都看才能完整判斷節點壓力。

💡 k3s containerd 鏡像管理完整流程

k3s 不使用 Docker daemon 而是用 containerd。部署流程：docker build 建置映像 → docker save 匯出 tar → sudo k3s ctr images import 匯入 containerd store → kubectl apply 部署。搭配 imagePullPolicy: Never 從本地 containerd 拉取，不需外部 registry。

# 建置
docker build -t myapp:latest .

# 匯入 k3s containerd
docker save myapp:latest | sudo k3s ctr images import -

# 部署
kubectl apply -f deployment.yaml

# 驗證
sudo k3s ctr images ls | grep myapp

💭 原理：k3s 為輕量內建 containerd 而非 Docker，本地開發環境用 k3s ctr images import 跳過 registry，適合單機或離線部署。

💡 systemd 服務管理：systemctl + journalctl

systemctl list-units --state=failed 列出所有啟動失敗的服務；journalctl -u <service> -n 50 --no-pager 看指定服務最近日誌；systemctl daemon-reload 在修改 unit file 後重載。改完設定後常用 systemctl restart 或 systemctl reload 套用。

# 列出失敗的服務
systemctl list-units --state=failed

# 查看特定服務最近 50 行日誌
journalctl -u my-app -n 50 --no-pager

# 重載 unit file
systemctl daemon-reload

# 重啟服務
systemctl restart my-app

💭 原理：systemd 是所有現代 Linux 發行版的 init 系統，journalctl 讀取二進位日誌（/var/log/journal），-u 過濾指定 unit。daemon-reload 重新掃描 unit 設定檔。

💡 Git stash 暫存管理

在切換 branch 或緊急修 bug 前，用 git stash 暫時儲存未 commit 的改動。用 stack（LIFO）結構管理多個暫存。git stash list 看所有暫存，git stash pop 還原並移除最新暫存，git stash -u 包含 untracked 檔案。

# 暫存目前改動（含 untracked）
git stash -u

# 看所有暫存
git stash list

# 還原最新暫存
git stash pop

# 套用但不移除
git stash apply

💭 原理：stash 以 stack 結構儲存工作目錄的 diff，stash@0 永遠是最新的。pop = apply + drop，適合快速切換上下文的開發情境。

💡 網路排查四指令：curl / dig / ss / nc

四指令涵蓋 OSI 應用層到傳輸層的網路診斷：curl -v 看完整 HTTP 請求流程與 SSL 握手；dig +short 簡潔 DNS 查詢；ss -tlnp 看 listening port 與對應 process；nc -zv 測試 TCP 連線是否通。

# HTTP 診斷（看 header + SSL）
curl -v https://example.com

# DNS 查詢
dig +short example.com

# 聽 port
ss -tlnp | grep 8080

# TCP 連線測試
nc -zv example.com 443

💭 原理：各指令對應不同 OSI 層——dig（DNS，應用層）、curl/v（HTTP+TLS，應用層/表現層）、ss（socket 統計，傳輸層+網路層）、nc（原始 TCP 連線測試，傳輸層）。由外而內逐步縮小問題範圍。
