💡 kubectl 診斷 Pod 啟動失敗的四步驟流程

Pod 啟動失敗時依序使用四指令：kubectl get pods 看整體狀態 → kubectl describe pod <name> 看 Events 和條件 → kubectl logs <name> 看容器輸出 → kubectl get events 看叢集層級事件。從 Status 欄位判斷類型：ImagePullBackOff（鏡像名稱錯誤或 registry 認證）、CrashLoopBackOff（容器啟動後 crash 不斷重啟）、OOMKilled（超過記憶體 limits）或 Pending（CPU/記憶體資源不足無法排程）。

kubectl get pods -A
kubectl describe pod  -n 
kubectl logs  -n 
kubectl get events --sort-by='.lastTimestamp'

💭 原理：describe pod 的 Events 欄位是診斷核心——記錄 kubelet 對 Pod 的每一個操作與錯誤訊息，是最快定位問題的入口。logs 取 container stdout/stderr，Events 取叢集控制平面記錄，兩者互補。

💡 k3s containerd 鏡像管理完整流程：離線部署

k3s 使用 containerd 而非 Docker daemon，離線部署流程：開發機上 docker build -t img:tag . → docker save img:tag > img.tar → 傳到 k3s 節點 → sudo k3s ctr images import img.tar → kubectl apply -f deploy.yaml。部署 YAML 需設 imagePullPolicy: Never，否則 kubelet 會嘗試從遠端 registry 拉取（pull timeout 後失敗）。

# 開發機
 docker build -t myapp:v1 .
 docker save myapp:v1 > myapp.tar

# k3s 節點
 sudo k3s ctr images import myapp.tar
 sudo k3s ctr images ls | grep myapp

# 部署 YAML
# imagePullPolicy: Never 必須設定

💭 原理：k3s 的 containerd 有自己的 image store，與 Docker 的 images 分離。k3s ctr import 會自動匯入到 k8s.io namespace 供 kubelet 使用。imagePullPolicy: Never 告訴 kubelet 跳過遠端拉取，直接使用本地 containerd 中的鏡像。

💡 OOM Killer 診斷：dmesg + exit code 137 判別法

當 Pod 或 process 被 OOM Killer 終止時，用 sudo dmesg -T | grep -i oom 查看核心 OOM 記錄，包含被殺的 process 名稱、pid、oom_score 以及當時記憶體使用量。exit code 137（128 + 9 SIGKILL）表示 process 被 OOM Killer 殺死。K8s 中 kubectl describe pod 的 Last State: OOMKilled 是 cgroup 層級 OOM，由 K8s memory limits 觸發。

sudo dmesg -T | grep -i oom | tail -10
kubectl describe pod  | grep -A 5 'Last State'
kubectl get pods -o wide | grep -E '(OOMKilled|Error|CrashLoop)'

💭 原理：Linux 核心有兩層 OOM：節點層（dmesg 記錄）殺系統 process；cgroup 層（K8s memory limits）只殺超過 limit 的容器 process，不影響其他 Pod。節點 OOM 更危險——可能連 kubelet 或 systemd 都被殺。

💡 Git stash 暫存管理：切換分支前的安全網

當你在分支 A 工作到一半需要切到分支 B 時，git stash 暫存所有未 commit 的改動（含 staged 和 unstaged），還原乾淨工作區。git stash -u 額外含 untracked 檔案。完成 B 的工作後，git stash pop 還原最近的暫存。git stash list 查看所有暫存（LIFO 堆疊）。git stash drop 丟棄特定暫存，git stash show -p 看暫存內容。

git stash -u          # 暫存含 untracked
 git stash list        # 看所有暫存
 git stash pop         # 還原最近暫存
 git stash drop stash@{1}  # 丟棄指定暫存
 git stash show -p stash@{0}  # 看暫存內容

💭 原理：git stash 本質是建立兩個 commit-like 物件（一個暫存索引，一個工作區），存於 .git/refs/stash 中。stash 堆疊是 LIFO（後進先出），可跨分支套用但可能衝突。

💡 Cloudflare DNS 管理：Proxy Mode vs DNS Only

Cloudflare DNS 有兩種模式：Proxy mode（橙色雲朵）流量經過 Cloudflare 全球 CDN，隱藏 origin IP 地址並提供免費 TLS 終止、DDoS 防護和快取加速；DNS only（灰色雲朵）直接解析到 origin IP，無 CDN 保護。用 dig +short example.com 檢查：回傳 Cloudflare IP 表示 Proxy mode，回傳真實伺服器 IP 表示 DNS only。可透過 Cloudflare API 程式化管理 DNS records，適合基礎設施即程式碼的自動化部署流程。

dig +short example.com                     # 查 DNS A 記錄
# 回傳 Cloudflare IP → Proxy mode
# 回傳真實 IP → DNS only

 curl -X GET "https://api.cloudflare.com/client/v4/zones/{zone_id}/dns_records" \
   -H "Authorization: Bearer {token}" \
   -H "Content-Type: application/json"

💭 原理：Proxy mode 的流量路徑是 client → Cloudflare edge → origin server，Cloudflare 會終止 TLS 並重新加密（Flexible/Full/Strict）。DNS only 的流量是 client → origin server 直連。Proxy mode 犧牲一點延遲換取安全與效能，適合 Web 流量；API 或串流服務用 DNS only 以避免 CDN 干擾。
