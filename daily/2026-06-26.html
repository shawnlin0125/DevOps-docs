💡 kubectl exec 進 Pod 內排查

kubectl exec -it <pod> -n <ns> -- sh 進入容器內互動式 shell。容器內常用的診斷三招：

# 確認環境變數是否正確注入
env | grep -i DB_HOST

# 測試 TCP 連線（取代 telnet）
nc -zv my-service 5432

# 確認 DNS 解析是否正常
cat /etc/resolv.conf
nslookup my-service

# 從本地複製檔案進/出 Pod
kubectl cp /local/file.txt <pod>:/remote/path -n <ns>

💭 原理：exec 開啟一個到容器內的 stream，透過容器內的 /bin/sh 執行程式。容器內要自備 nc（netcat）等工具，極簡 distroless 鏡像可能沒有這些指令，可改用 kubectl debug 或加裝 busybox。

💡 Linux 資源監控三指令：uptime / free / df

快速診斷系統健康的三個指令：

# CPU 排隊狀況 — load average > 核心數表示 CPU 不夠
uptime
# 範例輸出: load average: 4.52, 3.18, 2.01 (4 核 VM → 排隊中)

# 記憶體 — 重點看 available（不是 free）
free -h
# available 包含可立即回收的 page cache

# 磁碟 — 看使用率和 inode
df -h /
df -i /

💭 原理：Linux 會把閒置 RAM 拿去當作 page cache（檔案系統快取），所以 free 欄位偏低是正常的。available 才是真正可用的記憶體（含可回收快取）。load average 是 CPU 運行佇列長度，over 1.0 表示有行程在等 CPU，over 核心數則明顯超載。

💡 Git 復原操作：reset / restore / reflog

三種常用復原情境：

# 退回最近一次 commit，保留 staged 變更（修改仍在 index 中）
git reset --soft HEAD~1

# 退回 commit + unstaged，保留工作區檔案（可重新 commit）
git reset --mixed HEAD~1

# ⚠️ 捨棄所有未 commit 改動（不可逆！）
git reset --hard HEAD~1

# 丟棄工作區中某個檔案的改動
git restore <file>

# 救回誤刪的 commit（reflog 不被 push 到遠端）
git reflog
# 找到 deleted commit 的 hash 後：git checkout <hash> 或 git cherry-pick <hash>

💭 原理：reset 是移動 HEAD 指標，--soft / --mixed / --hard 決定是否同步更新 index（staging area）和工作目錄。reflog 記錄本地所有 HEAD 移動（含 reset 和 rebase），是 Git 的本地時光機。restore 是新版 Git（2.23+）取代 checkout 的部分功能，語意更清楚。

💡 Git stash 暫存管理

切換 branch 前暫存未 commit 的改動：

# 暫存所有改動（含 untracked 檔案用 -u 或 --include-untracked）
git stash push -m "WIP: feature X partial"
git stash -u   # 含 untracked files

# 查看所有暫存（LIFO 堆疊，最新在最上面）
git stash list
# stash@{0}: On feature/x: WIP: feature X partial
# stash@{1}: On main: fix typo in config

# 還原最近一個 stash 並從堆疊移除
git stash pop

# 還原特定 stash 但不從堆疊移除
git stash apply stash@{2}

# 丟棄特定 stash
git stash drop stash@{1}

💭 原理：stash 本質是 commit-like 的物件，存放在 .git/refs/stash 參照的 stack 中。pop 會嘗試自動 merge，如果與目前工作區衝突需要手動解決。stash 只能追蹤 tracked 檔案，-u 會記錄 untracked 但不追蹤 ignored 檔案（除非再加 -a）。

💡 Helm 常用操作：生命週期管理

Helm release 管理的核心指令：

# 列出所有 namespace 的 release
helm list -A

# 查看某個 release 的版本歷史（含 revision number）
helm history my-release -n my-namespace

# 升級失敗時快速回退到指定版本
helm rollback my-release <revision> -n my-namespace

# 查看目前生效的 values（除錯用）
helm get values my-release -n my-namespace

# 安全檢查最終渲染結果（不實際部署）
helm template my-release ./chart -f values/prod.yaml --debug

💭 原理：Helm 每次 upgrade 或 install 都會建立新的 revision（版本）。rollback 不是真的「回退」操作，而是用舊 revision 的 manifest 建立一個新 revision（即 revision +1）。--reuse-values 可以保留之前手動 --set 的參數，但可能與新的 values 衝突。
