💡 kubectl 看資源使用：top + Allocated

用 kubectl top nodes 看即時 CPU/RAM 用量，kubectl top pods -A 看每個 Pod 的即時用量。kubectl describe node 搭配 grep 看 Allocated resources（request/limit 佔比）——這是 scheduler 視角，顯示節點上「已承諾分配」的資源比例，比 top 更能預測是否能排程新 Pod。

# 即時用量（實際正在使用的資源）
kubectl top nodes
kubectl top pods -A

# Scheduler 視角：已分配資源佔比（request/limit）
kubectl describe node <node-name> | grep -A 8 Allocated

💭 原理：top 是即時的 /proc/stat 用量；describe node Allocated 是 scheduler 計算 Pod requests 的累加值。top 低不代表可以塞 Pod——如果 request 已經佔滿，新的 Pod 還是會 Pending。

💡 k3s containerd 鏡像管理完整流程

k3s 預設用 containerd 而非 Docker daemon。部署本地鏡像的流程：docker build → docker save img:tag | sudo k3s ctr images import - → kubectl apply → kubectl rollout restart。鏡像存在 containerd 的 local image store，不需要 registry。記得設定 imagePullPolicy: Never 避免 kubelet 去拉 remote。

# 1. Build image
docker build -t myapp:latest .

# 2. 匯入到 k3s containerd
docker save myapp:latest | sudo k3s ctr images import -

# 3. 驗證匯入成功
sudo k3s ctr images list | grep myapp

# 4. 部署（imagePullPolicy: Never）
kubectl apply -f deploy.yaml
kubectl rollout restart deployment/myapp

💭 原理：k3s 的 containerd 有獨立的 image store，Docker 的 image 不會自動同步過去。docker save 把 image 匯出成 tar，k3s ctr images import 解壓匯入到 containerd namespace。

💡 systemd 服務管理：systemctl + journalctl

三個最常用的 systemd 診斷指令：systemctl list-units --state=failed 列出失敗服務；journalctl -u <service> -n 50 --no-pager 看特定服務的最近日誌；改完 unit file 後要先 systemctl daemon-reload 再 restart。

# 看所有失敗的服務
systemctl list-units --state=failed

# 看特定服務的最近日誌
journalctl -u nginx -n 50 --no-pager

# 改完 /etc/systemd/system/xxx.service 後重載
sudo systemctl daemon-reload
sudo systemctl restart xxx

# 看服務狀態（含最近日誌）
systemctl status xxx --no-pager -l

💭 原理：systemd 用 cgroup 管理 process，startup type 有 simple/forking/oneshot 等。daemon-reload 重新解析 unit file，restart 後新的 unit 設定才生效。status 同時顯示 process state 和最近 log。

💡 Git stash 暫存管理

切換 branch 前忘了 commit 時，用 git stash 暫存目前改動（LIFO stack）。git stash push -u 連 untracked files 一起存。git stash list 看所有暫存，git stash pop 還原最近的一次並從 stack 移除，git stash apply 只還原不移除。

# 暫存目前改動（含 untracked files）
git stash push -u -m "WIP: 實驗中功能"

# 看所有暫存
git stash list

# 還原最近暫存（並從 stack 移除）
git stash pop

# 只還原不移除（保留 stash 副本）
git stash apply stash@{0}

# 丟棄特定暫存
git stash drop stash@{0}

💭 原理：stash 本質是一個 commit-like 的物件存在 .git/refs/stash，用 LIFO stack 管理。push 時自動做一個 soft reset 回到 HEAD，pop 時 apply 後 reset 回原本的 working tree 狀態。

💡 Helm 常用操作：生命週期管理

helm list -A 看所有 namespace 的 release；helm history <release> -n <ns> 看版本歷史（含 revision 號碼和 deployed/failed 狀態）；helm rollback <release> <rev> -n <ns> 退回指定版本；helm get values <release> -n <ns> 看目前生效的 values 設定。

# 所有 release
helm list -A

# 版本歷史
helm history myapp -n production

# 退回 revision 2
helm rollback myapp 2 -n production

# 看目前生效的 values
helm get values myapp -n production

# 加上 --reuse-values 保持現有 values 做 upgrade
helm upgrade myapp ./chart --reuse-values -n production

💭 原理：Helm 每個 upgrade/install 都產生一個新的 revision，舊的 revision 保留（預設 10 個）。rollback 本質是建立一個「退回版本」的新 revision，不是真的刪除。--reuse-values 用上次 deploy 的 values 避免覆蓋。
