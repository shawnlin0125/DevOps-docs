💡 kubectl 診斷 Pod 啟動失敗的完整流程

用 kubectl get pods → describe → logs → events 四步驟，從 Status/Events 欄位判斷是 ImagePullBackOff、CrashLoopBackOff、OOMKilled 還是 Pending

# 1. 看 Pod 狀態（STATUS 欄位顯示問題類型）
kubectl get pods -n 

# 2. 看詳細事件（找出根本原因）
kubectl describe pod  -n 

# 3. 看容器日誌（應用層錯誤）
kubectl logs  -n 

# 4. 看 cluster 層級事件
kubectl get events -n  --sort-by=.lastTimestamp

💭 原理：這四個指令從不同層級切入：get pods 看症狀、describe 看 Infrastructure 層事件（ImagePull/VolumeMount）、logs 看應用層錯誤、get events 看時間線，缺一不可。

💡 k3s containerd 鏡像管理完整流程

k3s 不用 Docker registry，需要 docker build 後手動 docker save 並用 sudo k3s ctr images import 匯入 containerd image store，Deployment 需設 imagePullPolicy: Never

# 1. 用 Docker build 鏡像
docker build -t myapp:latest .

# 2. 匯出為 tar 檔
docker save myapp:latest | sudo k3s ctr images import -

# 3. 確認匯入成功
sudo k3s ctr images ls | grep myapp

# 4. 部署（imagePullPolicy 設 Never 才不會去 registry 拉）
kubectl apply -f deployment.yaml
kubectl rollout restart deployment/myapp -n

💭 原理：k3s 使用 containerd 作為 CRI runtime，它有自己的 image store 獨立於 Docker。docker save + ctr import 是繞過 registry 直接將鏡像餵給 containerd 的方法。imagePullPolicy: Never 確保 K8s 不嘗試從遠端拉取。

💡 查 OOM 紀錄與 exit code 137 判別

用 sudo dmesg -T | grep -i oom 看核心 OOM Killer 紀錄；K8s 中 Pod 被 OOM 殺掉會顯示 OOMKilled (exit code 137 = 128 + SIGKILL 9)

# 看系統 OOM Killer 紀錄
sudo dmesg -T | grep -i oom

# 看特定 Pod 的 exit code（已重啟的要看 Previous）
kubectl get pod  -n  -o jsonpath='{.status.containerStatuses[0].lastState.terminated.exitCode}'

# 或直接用 describe（看 Last State: Terminated → Reason: OOMKilled）
kubectl describe pod  -n

💭 原理：exit code 137 = 128 + 9(SIGKILL)，代表被 OOM Killer 強制終止。dmesg 看的系統層級 OOM（所有 process 競爭實體 RAM），K8s 的 cgroup OOM（Pod 超過 memory limits）不一定會出現在 dmesg。

💡 Git stash 暫存管理

git stash 把工作區和暫存區的改動暫存到 stash stack（LIFO），方便切換 branch 或做其他事。支援含 untracked 檔案（-u）、顯示暫存清單、還原指定 stash

# 暫存所有改動（含 untracked 檔案）
git stash -u

# 看所有暫存
git stash list
# 輸出: stash@{0}: On feature/xxx: WIP on ...

# 還原最近的暫存（同時從 stack 移除）
git stash pop

# 還原但不移除
git stash apply stash@{1}

# 移除指定的暫存
git stash drop stash@{0}

💭 原理：stash 本質是 commit-like 物件存在 .git/refs/stash，用 LIFO stack 管理。pop = apply + drop。stash 很適合切 branch 前忘記 commit 的場景，但長期放著不如開一個 WIP branch。

💡 網路排查四指令：curl / dig / ss / nc

curl -v 看完整 HTTP request/response + SSL 握手、dig +short 做 DNS 解析、ss -tlnp 看 listening port 與所屬 process、nc -zv 測試 TCP 連線通不通

# 應用層：看 HTTP response header + body
curl -v http://example.com

# DNS 層：快速查 A record
dig +short example.com
# 或查特定 DNS 伺服器
dig @8.8.8.8 +short example.com

# 傳輸層：看哪些 port 在 listen（取代 netstat）
ss -tlnp

# 傳輸層：測端口是否可連線
nc -zv example.com 443

💭 原理：這四指令分別對應 OSI 四層：curl (L7 HTTP/HTTPS)、dig (L5 DNS)、ss (L4 TCP socket 狀態)、nc (L4 TCP connectivity)。從上層一路測到下層，快速定位問題在哪一層。
