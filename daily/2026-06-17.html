💡 kubectl exec 進 Pod 內排查

kubectl exec -it -n -- sh 進容器互動。常用診斷指令：env | grep -i 確認環境變數、nc -zv 測試連線、cat /etc/resolv.conf 確認 DNS 設定。Pod CrashLoopBackOff 時用 ephemeral container 或 kubectl debug 方式排查。

kubectl exec -it  -n  -- sh

💭 原理：exec 在 Pod 網路 namespace 內建立 process，等同在容器內部操作，可直接驗證 env/DNS/連線等執行期設定

#A kubectl exec debug pod troubleshooting k8s network dns

💡 Git 復原操作：reset / restore / reflog

git reset --soft HEAD~1 退回 commit 保留 staged、git restore 丟棄工作區改動、git reflog 看所有 HEAD 移動記錄救回誤刪 commit。區別：reset 動 branch pointer、restore 動 working tree、reflog 是救命的操作日誌。

git reflog && git reset --soft HEAD@{1}

💭 原理：Git 不會立即刪除物件，reflog 記錄所有 HEAD 變動，只要 commit 在 reflog 保留期內（預設 90 天）就還能 git reset 救回

#D Git reset restore reflog 版本控制 復原

💡 Helm values 分層覆蓋與 --set 陷阱

Helm 三層值覆蓋：values.yaml（預設）← values/production.yaml（環境覆蓋）← --set key=value（CLI 覆蓋）。後層 merge 覆蓋前層同名 key。helm template --debug 檢查渲染結果，helm get values -n 看生效值。--set 常見陷阱：typo 無人檢查、複雜結構需 JSON 語法。

helm template --debug  -f values/production.yaml --set image.tag=latest .

💭 原理：Helm 用 Go template 合併 values，三次 yaml merge 的優先級：--set > --values > 內建 values.yaml，同層 array 無法部分覆蓋只能整個取代

#E Helm values override deploy k8s helm template

💡 Linux 資源監控三指令：uptime / free / df

uptime 的 load average > CPU 核心數表示 CPU 排隊。free -h 要看 available 欄位（真實可用記憶體），free 欄位低不代表 RAM 不足因為 Linux 拿閒置 RAM 做 cache。df -h / 看磁碟使用率，通常 80% 告警 90% 緊急；df -i 查 inode 用量。

uptime && free -h && df -h / && df -i /

💭 原理：load average 是 running+uninterruptible 行程數，free 的 available 包含可回收 cache，比 free 欄位更準確反映記憶體壓力

#C Linux monitoring uptime free df CPU memory disk

💡 網路排查四指令：curl / dig / ss / nc

四指令對應 OSI 四層：curl -v 看完整 HTTP/HTTPS 流程與 SSL 握手、dig +short 快速 DNS 解析、ss -tlnp 看 listening port 與所屬 process（取代 netstat）、nc -zv host port 測試 TCP 連線。先 dig 確認 DNS 正常，再 curl 看應用層，中間用 nc 測傳輸層。

dig +short example.com && curl -vI https://example.com && ss -tlnp | grep :443 && nc -zv example.com 443

💭 原理：curl -v 顯示完整 HTTP request/response header 含 SSL 憑鏈，dig +short 跳過 local DNS cache 直接查上游，ss 用 kernel socket API 比 /proc 更快

#F network curl dig ss nc troubleshooting DNS TCP
