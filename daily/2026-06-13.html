💡 kubectl exec 進 Pod 內排查

kubectl exec -it -n -- sh 進入容器內。常用診斷指令：env | grep 確認環境變數、nc -zv 測試服務連通性、cat /etc/resolv.conf 確認 DNS 設定、df -h 看磁碟、top 看 process。注意：容器內通常沒有 curl/vim，用 wget -qO- 替代 curl。

💭 原理：kubectl exec 啟動一個 process 在容器內執行，共用容器 namespace（pid/net/ipc），所以容器內看到的 env、DNS、process 就是 Pod 的真實狀態。nc -zv 發送 SYN 封包確認 port 通不通，類似 telnet 但更輕量。

💡 查 OOM 紀錄：dmesg + exit code 137

sudo dmesg -T | grep -i oom 查系統 OOM Killer 紀錄。K8s 中 Pod 因記憶體不足被殺會顯示 OOMKilled（exit code 137 = 128 + SIGKILL 9）。Pod memory limits 總和超過實體 RAM 時會連鎖殺 Pod。查看 Pod 資源：kubectl describe pod | grep -A 2 Limits。

💭 原理：OOM Killer 是 Linux 核心在 memory pressure 超出臨界值時觸發的機制。exit code 137 = 128 + 9(SIGKILL)，K8s 從 exit code 判斷是正常退出還是被 OOM 殺死。Pod Memory limits 設定不當是 OOM 主因，建議預留 20% overhead。

💡 Git 復原操作三步驟

git reset --soft HEAD~1 退回 commit 但保留 staged 變更（可重新 commit）、git restore 丟棄工作區未暫存改動、git reflog 查看所有 HEAD 移動記錄可救回誤刪的 commit。--soft 不改工作區和 index，--mixed 退回 staged 但不動工作區，--hard 全部丟棄（謹慎使用）。

💭 原理：Git 的資料模型是 immutable DAG（有向無環圖），reset 只是移動 HEAD 指標，commit object 不會立刻消失。reflog 記錄了 HEAD 的每一步移動，預設保留 90 天，是救回誤操作的最後防線。

💡 Cloudflare DNS 管理：Proxy vs DNS only

Cloudflare Proxy mode（橙色雲朵）隱藏 origin IP 並提供免費 TLS 終止、DDoS 防護、CDN 快取。DNS only（灰色雲朵）直接解析到 origin IP，無保護但延遲更低。透過 Cloudflare API 管理 DNS record 可自動化：curl -X POST https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records -H 'Authorization: Bearer $TOKEN'。

💭 原理：Cloudflare Proxy 模式本質是一個反向代理：流量先到 Cloudflare Edge，由它 terminate TLS、apply security rules、cache static content，再用自有憑證轉發到 origin。DNS only 則直接回 origin IP。選擇依據：需要安全/CDN 用 Proxy，需要即時連線（SSH/WebSocket）用 DNS only。

💡 Helm values 分層覆蓋與 --set 陷阱

Helm values 三層覆蓋順序：values.yaml（chart 預設）← values/production.yaml（環境覆蓋）← --set key=value（CLI 最終覆蓋）。後層 merge 蓋前層同名 key。--set 方便但 typo 不會報錯（無效 key 直接忽略），建議 production 環境用 -f 檔案而非 --set。helm template --debug 可預覽渲染結果。

💭 原理：Helm values 的 merge 策略是 shallow merge：list 型（如 containers[]）會整份取代，不會 append。--set 對巢狀 key 用點語法（service.port=8080），但無法對 list 元素設值。values.schema.json 可以驗證使用者輸入，防止 typo 造成無效設定。
